# template/ — 화면을 그리는 곳

프론트 화면 전부가 여기 있다. **커뮤니티(게시판·회원)와 쇼핑몰이 같은 템플릿 하나를 쓴다** —
색을 바꾸면 양쪽이 함께 바뀐다. 관리자 화면(`adm/`)은 여기 소관이 아니다.

고르는 곳은 **관리자 환경설정 한 곳뿐**이다(`cf_template`). `template/` 아래 폴더가 목록에 그대로 뜬다.
예전에 `config.php` 에서도 고를 수 있었는데, 값이 두 곳에 있고 하나가 조용히 이기는 구조라 걷어냈다.

각 템플릿의 성격과 금기는 `template/<이름>/DESIGN.md` 한 장에 있다. 작업 전에 그것부터 읽는다.

지금 있는 템플릿은 둘이다 — **`standard`**(기본, shadcn 계열: 실선·중성·강조색 하나)와
**`old-standard`**(옛 기본, 소다 블루 바탕에 카드가 그림자로 떠 있던 것). 새 작업은 `standard` 에 한다.

---

## 1. 토큰이 원천이다 — 리터럴 색을 쓰지 않는다

`style.css` 맨 위 `:root` 블록이 그 템플릿의 전부다. 화면 규칙은 값을 직접 적지 않고 토큰만 부른다.

```css
color: #35C5F0;        /* ✗ 템플릿을 바꿔도 이 색은 안 바뀐다 */
color: var(--accent);  /* ✓ */
```

**실제로 이것 때문에 물렸다.** `.cart-cta`(바로구매 버튼)에 시그니처 민트가 박혀 있어서, 템플릿을
갈아도 버튼만 옛 색으로 남았다. 같은 파일 주석에 "민트는 스코프 변수로만 쓴다"고 적혀 있었는데도 그랬다.

새 색이 필요하면 **토큰을 먼저 만들고** 규칙이 그걸 부르게 한다. 예외는 둘뿐이다 —
SNS 공유 버튼의 브랜드 색(페이스북 파랑 등)과, 어두운 덮개 위에서만 사는 색(라이트박스 안).

## 1-1. 뜻은 모듈이, 색은 템플릿이 정한다

같은 값을 여러 화면·여러 템플릿이 색으로 표시해야 할 때가 있다(주문 상태가 그렇다).
**뜻(갈래)은 모듈 PHP 에 한 곳으로 두고, 색은 템플릿마다 자기 팔레트로 정한다.**

```php
cart_order_status_tone($od['od_status'])   // 'wait' | 'go' | 'ship' | 'done' | 'bad' | 'end'
```
```blade
<span class="cart-status is-{{ cart_order_status_tone($od['od_status']) }}">{{ $od['status_label'] }}</span>
```

화면(blade)은 한 벌이고 클래스 이름도 한 벌이다. 그래서 `standard` 는 중성 팔레트의 색으로,
`old-standard` 는 소다 블루로 같은 뱃지를 그린다 — **뜻은 같고 색만 갈린다.**

- 색을 화면이나 PHP 에서 고르지 않는다. PHP 가 색 이름(`red`)을 돌려주면 템플릿이 색을 못 바꾼다.
- 갈래는 원본 값(`od_status`)으로 고른다. 표시 글자로 고르면 안 된다 — 같은 상태가 결제수단에
  따라 "입금대기/결제대기" 로 갈리므로 글자로 고르면 한쪽만 색이 빠진다.
- **템플릿을 새로 만들면 갈래 전부를 그려야 한다.** 하나라도 빼면 그 상태만 맨 뱃지가 된다.
  주문 상태는 여섯이다: `is-wait` · `is-go` · `is-ship` · `is-done` · `is-bad` · `is-end`.
- 갈래를 늘리거나 줄이는 것은 모듈 쪽 결정이다. 늘렸으면 **모든 템플릿**에 규칙을 추가한다.

## 2. 비슷해 보이는 토큰 고르기

| 고민 | 규칙 |
|---|---|
| `--line` / `--btn-line` | `--line` 은 **장식용** 실선(카드 테두리·구분선). `--btn-line` 은 **누를 수 있는 것**의 경계(버튼·입력칸) — 3:1 을 지켜야 하므로 더 진하다. 헷갈리면 후자 |
| `--bg` / `--card` / `--row-hover` | `--bg` 바탕, `--card` 그 위에 올라가는 면, `--row-hover` 는 줄에 마우스가 닿았을 때. 카드 안의 옅은 면도 `--row-hover` 를 쓴다 |
| `--sh-sm` / `--sh-md` / `--sh-lg` | 앞의 둘은 **평범한 면**, `--sh-lg` 는 **진짜로 떠 있는 것**(드롭다운·모달·라이트박스). 이 구분이 있어야 템플릿이 "그림자를 안 쓰는" 방향으로 갈 때 뜬 것만 남길 수 있다 |
| `--accent` / `--accent-deep` / `--accent-soft` | 채움 / 그 위 글자·hover / 옅은 배경. 링크 글자는 `--accent-deep`(밝은 바탕에서 `--accent` 는 대비가 얕다) |
| `--muted` | 흐린 글자 전용. 선이나 면에 쓰지 않는다 |

## 3. 대비는 계산해서 맞춘다

이 프로젝트는 **주석에 대비율을 적는 문화**가 있다(`/* 채움 위 5.29:1 */`). 새 색을 넣을 때도 그렇게 한다.

- 본문 글자 **4.5:1**
- 큰 글자·굵은 버튼 글자·**조작 요소 경계** **3:1** (WCAG 1.4.11)
- 장식용 선은 기준 없음

밝은 모드와 어두운 모드를 **각각** 재야 한다. 어두운 모드에서 강조색은 밝아지므로 그 위 글자는
검정 쪽이 맞는 경우가 많다(`--accent-fg` 가 어두운 값인 이유).

## 4. 함정

**`[hidden]` 이 진다.** 브라우저 기본 `[hidden]{display:none}` 은 특이도가 가장 낮아,
컴포넌트에 `display:flex` 를 주면 `hidden` 을 걸어도 그대로 보인다. 이 저장소에는 이걸 한 곳씩
막은 규칙이 다섯 개 쌓였고 그러고도 여섯 번째가 남아 있었다. **모든 템플릿은 맨 위에
`[hidden] { display: none !important; }` 를 둔다.**

**어두운 모드는 세 곳에 적는다.** `@media (prefers-color-scheme: dark)` 만으로는 부족하다 —
사용자가 테마 토글을 누르면 `data-theme` 이 루트에 붙는데, 그게 미디어쿼리를 **양방향으로** 이겨야 한다.
`:root[data-theme="dark"]` 와 `:root[data-theme="light"]` 를 함께 둔다. 값이 세 곳에 흩어지므로,
손으로 적지 말고 한 곳에서 뽑아 만든다.

**그 세 곳에 `color-scheme` 도 함께 적는다.** 브라우저가 직접 그리는 것들 — 셀렉트 펼침 목록,
스크롤바, 날짜 선택기 — 은 CSS 로 색을 줄 수 없고, 어둡다고 알려 주는 손잡이가 이것 하나뿐이다.
빠뜨리면 어두운 화면에서 셀렉트를 펼치는 순간 **흰 목록에 흐린 글자**가 뜬다(`option` 은 `--fg` 를
물려받는데 목록 바탕은 브라우저 기본 흰색으로 남는다). `option { background-color: var(--card) }` 도
함께 둔다 — 리눅스 크롬처럼 `option` 색을 CSS 에서 받는 곳이 있다.

**BladeOne 은 붙은 지시자를 컴파일하지 않는다.** `텍스트@if` 처럼 앞에 글자가 붙으면 그대로 출력된다.
줄 첫머리에 두거나 앞에 공백을 준다. `{{-- --}}` 주석 안에 `{!!` 를 적으면 그다음 echo 가 깨진다.
`@include` 에 루프 변수는 자동으로 안 넘어간다 — 배열로 명시해 넘긴다.

**클래스 이름은 화면 밖에서도 유일해야 한다.** 템플릿 하나가 커뮤니티·게시판·쇼핑몰·상품 상세를
모두 그리고 CSS 도 한 파일이다 — "장바구니 화면의 .cart-pick" 같은 것은 없다.
실제로 장바구니 체크박스에 `.cart-pick` 을 붙였다가, 상품 상세에서 같은 이름을 쓰던 "고른 옵션 줄"이
`width:18px` 을 받아 세로로 찌그러졌다. 새 클래스는 먼저 `grep` 해 보고 짓는다.

**그림자 토큰은 모양을 바꾸는 손잡이다.** `--sh-md` 를 `0 0 0 1px var(--line)` 로 두면 그림자를 쓰던
컴포넌트 수십 곳이 규칙을 한 줄도 안 고치고 실선 테두리가 된다(지금 `standard` 가 이 방법을 쓴다).

## 5. 확인하는 법

**루트 미리보기** — `https://<도메인>/?template=<이름>` 은 **메인 화면에서만** 먹는다(다른 화면은
템플릿별 코드 차이가 뒷문이 될 수 있어 막아 두었다). DB·세션을 안 건드리므로 링크를 타고 나가면 원래대로다.

**전 화면 확인** — 관리자 환경설정에서 템플릿을 바꾼다. 되돌리는 것도 같은 자리에서 1초다.

**최소한 이 화면들은 본다**: 메인 · 게시판 목록(표·카드·갤러리) · 글 읽기 · 로그인 · 스토어홈 ·
상품 목록 · 상품 상세(옵션 칩!) · 장바구니 · 주문서 · 주문 상세. **밝은 모드와 어두운 모드 둘 다.**

## 6. 새 템플릿 만들기

1. `cp -r template/standard template/<이름>`
2. `style.css` 맨 위 `:root` 서문만 갈아 끼운다. 컴포넌트 규칙은 되도록 건드리지 않는다 —
   토큰만으로 안 되는 것이 나올 때만 그 규칙을 고치고, 왜 고쳤는지 주석을 남긴다.
3. `template/<이름>/DESIGN.md` 를 한 장 쓴다(성격 한 문단 + 하지 말 것 목록).
4. 관리자 환경설정 목록에 자동으로 뜬다. 코드에 이름을 등록하는 곳은 없다.

## 7. 문서를 쓸 때

**색 값을 이 문서에 베껴 적지 않는다.** CSS 가 원천이고, 문서에 값을 적는 순간 두 곳이 되어
하나가 조용히 틀려진다. 여기에는 **값이 아니라 고르는 규칙**만 적는다.
한 장을 넘기면 안 읽고, 안 읽으면 어긋나고, 어긋난 문서는 없느니만 못하다.
