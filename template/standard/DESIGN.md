# standard — Slate 중성 + 소다 블루 하나 (shadcn 계열)

먼저 [`template/CLAUDE.md`](../CLAUDE.md)(전 템플릿 공통 규약)를 읽는다. 여기에는 이 템플릿만의 성격을 적는다.

> 이 템플릿이 **기본**이다(`cf_template = standard`). 예전 기본은 `old-standard` 로 남아 있다 —
> 소다 블루 바탕에 카드가 그림자로 떠 있던 그 화면이다. 되돌려 보고 싶으면 관리자 환경설정에서 고르면 된다.

**shadcn/ui 를 설치해 쓰는 것이 아니다.** 그건 React + Tailwind + Radix 묶음이라 이 프로젝트(PHP +
BladeOne)에 들어오지 않는다. 가져온 것은 라이브러리가 아니라 **몇 가지 규칙**이다.

> 면은 그림자로 띄우지 않고 실선으로 나눈다 · 강조색은 하나뿐이다 · 색은 상태에만 쓴다 ·
> 포커스는 언제나 보인다 · 모서리와 여백은 눈금에서 벗어나지 않는다

---

## 하지 말 것

- **그라디언트** — 이 템플릿에는 하나도 없다. 쓰던 자리는 단색 강조(`--grad: var(--accent)`)로 받는다.
- **카드에 그림자** — 카드·패널·목록은 실선으로 나눈다. 그림자는 드롭다운·모달·라이트박스처럼
  **정말로 떠 있는 것**만(`--sh-lg`).
- **알약 버튼**(`border-radius: 999px`) — 버튼은 `--r-btn`(8px). 알약은 칩·배지 같은 작은 표시에만.
- **강조색을 두 개 이상** — 쇼핑몰용 민트, 영역 전환용 주황 같은 두 번째 색을 들이지 않는다.
  standard 는 그 색들을 썼지만, 강조가 하나뿐인 여기서는 그 색이 사이트 어디에도 없어 되레 붕 뜬다.
- **색으로 분류하기** — 아래 참고.

## 색은 "무엇인가"가 아니라 "봐야 하는가"에만

칩이 세 역할로 갈린다. **분류·게시판 이름 같은 이름표는 전부 중성**이다.

| 역할 | 토큰 | 붙는 곳 |
|---|---|---|
| 이름표 | `--chip-bg` / `--chip-fg` | 게시판 분류, 그룹명, 상품명, 손님 수 — `.chip`, `.chip.c2/c3/c4`, `.chip.cate` |
| 봐야 할 것 | `--notice-bg` / `--notice-fg` | 공지 — `.chip.notice` |
| 지금 내가 있는 자리 | `--accent-soft` / `--accent-deep` | 열람 중인 글 — `.chip.here` |

**분류를 색으로 가르지 않는 이유는 미학이 아니라 개수다.** 분류는 관리자가 게시판마다 자유롭게
늘리는데, 여덟 개가 되는 순간 서로 구별되면서 대비도 맞는 색 여덟 개를 골라야 한다. 그건 불가능하다.
글자가 이미 이름을 말하므로 색이 할 일이 없다.

`c2/c3/c4` 는 다른 화면들이 이름으로 부르고 있어 클래스를 지우지 않았다 — **값만 중성으로 접었다.**
새 화면을 만들 때는 이 클래스들을 쓰지 말고 `.chip` 하나로 충분하다.

## 글자·여백 눈금을 한 급씩 올렸다

옛 기본(`old-standard`)의 본문 13.5px 는 관리자 화면에서 온 조밀한 눈금이다. **shadcn 이 모던해 보이는 이유의
절반은 색이 아니라 여기 있다** — 색만 바꾸면 "별로 안 달라졌다" 는 말을 듣는다.

| | old-standard | 지금 |
|---|---|---|
| 본문 `--t-base` | 13.5px | **14px** |
| 큰 제목 `--t-2xl` | 25px | **30px** |
| 카드 안쪽 여백 | 16/24px | **24px** |
| 버튼·입력칸 높이 | 제각각 | **36px 로 통일**(padding 9px) |
| 본문 행간 | 1.55 | **1.6** |
| 제목 자간 | -.01em | **-.021em** |
| 게시판 목록 행 | 위아래 12px | **14px**(제목만 15px, 나머지 칸은 13px) |

버튼과 입력칸이 나란히 놓이는 자리가 많아 **키를 하나로 맞추는 것**이 특히 크다 —
제각각이면 줄이 들쭉날쭉해 손으로 만든 티가 난다.

## 확인 대화상자는 직접 그린다

브라우저 `confirm()` 은 운영체제가 그리는 창이라 **CSS 가 한 줄도 안 먹는다.** 공들여 만든 화면 위에
회색 시스템 창이 뜨면 거기서 디자인이 끊긴다. shadcn 의 `AlertDialog` 자리를 `theme.js` 의
`g5Confirm()` 이 대신한다.

```js
g5Confirm('정말 지울까요?', function () { ... })          // 코드에서
<form data-confirm="정말 지울까요?">                       // 화면에 적어 둘 때
<a href="…" data-confirm="…" data-confirm-danger>         // 되돌릴 수 없는 처리(빨간 확인 버튼)
```

`confirm()` 과 달리 **값을 돌려주지 않는다** — 스크립트를 멈춰 세우는 것은 브라우저만 할 수 있다.
할 일을 콜백으로 넘긴다. Esc·덮개 클릭은 취소, Tab 은 두 버튼 안에 갇힌다.

**템플릿 안에 시스템 confirm 은 하나도 남지 않았다**(cart·bbs·shop 16곳 전부 변환).
링크에 붙은 것은 `data-confirm` 으로, JS 안에 있던 것은 콜백으로 바꿨다 —
후자는 "일단 멈추고, 확인을 받으면 같은 동작을 다시 일으키되 플래그로 두 번 묻지 않는다" 는 꼴이다.

## 수량칸은 한 벌뿐이다

`.cart-qty`(−·입력칸·+)는 **장바구니 · 상품 상세의 고른 옵션 줄 · 옵션 없는 상품의 구매 폼**
세 곳에 나오는데, 규칙은 `theme.js` 의 `g5Qty*` 한 곳에만 있다.

```js
g5QtyPaint($box)                 // 한계에 닿은 버튼을 흐리게(is-limit + aria-disabled)
g5QtyNext(btn, minusHint)        // 다음 값, 한계면 그 자리에 이유를 띄우고 null
g5QtyClamp($box)                 // 직접 쳐 넣은 값 자르기
g5QtyMax($box)                   // 0 이면 품절, 음수면 "아직 모름"(옵션 고르기 전)
```

- **한계에서 `disabled` 를 쓰지 않는다.** 브라우저가 클릭을 안 넘겨줘서 "왜 안 되는지" 를
  말할 기회가 사라진다. 흐리게만 칠하고, 누르면 누른 자리에 `g5Toast` 로 이유를 띄운다.
- 재고는 `data-max` 로 싣되 **읽을 때는 `.data('max')`** 를 쓴다 — 장바구니는 저장 뒤 서버가
  알려 준 재고를 `.data('max', n)` 으로 다시 심는데 그건 속성을 안 고친다.
- 저장 방법만 화면마다 다르다(장바구니는 ajax 즉시 저장, 상세는 폼 제출).
  전에 화면마다 따로 만들었다가 크기·테두리·말투가 모두 갈렸다.

## 이 템플릿만의 장치 — 그림자 토큰을 1px 링으로

```css
--sh-sm: 0 0 0 1px var(--line);   /* 그림자가 아니라 실선 */
--sh-md: 0 0 0 1px var(--line);
--sh-lg: 0 10px 30px …, 0 0 0 1px var(--line);   /* 진짜 떠 있는 것만 */
--sh-btn: none;
```

`box-shadow: var(--sh-md)` 를 쓰던 **컴포넌트 32곳을 한 줄도 안 고치고** 실선 테두리로 바꾼다.
컴포넌트 규칙을 건드리지 않았으므로 standard 와의 차이가 서문에만 남고, 나중에 standard 가 바뀌어도
따라가기 쉽다. 새 컴포넌트를 만들 때도 **테두리를 직접 긋지 말고 `--sh-md` 를 부르면** 자동으로 맞는다.

## standard 와 달라진 결정

| 무엇 | 왜 |
|---|---|
| 메인 머리말에서 그라디언트 띠를 걷고 숫자(회원·전체 글)를 둠 | 화면에서 가장 강한 요소였는데 담고 있던 것은 인사말 한 줄뿐이었다 |
| 메인 카드·설문·접속자의 라벨 칩 제거 | `[공지] 공지사항` 처럼 칩과 제목이 같은 말을 두 번 했다 |
| 카드 격자 `align-items: start` | stretch 로 두면 글이 하나뿐인 공지 카드가 옆 카드 키에 맞춰 늘어나 큰 빈칸이 생긴다 |
| 카드 목록 줄에 구분선, **설문·접속자 카드는 예외** | 선을 그으면 고를 수 있는 항목이 표의 행처럼 읽힌다 |
| 영역 전환(커뮤니티·쇼핑몰)을 세그먼트 컨트롤로 | standard 는 두 칸을 파랑·주황으로 갈랐는데, 강조가 하나면 둘 다 파래져 어느 쪽이 켜졌는지 안 읽힌다. 색이 아니라 "떠 있음"이 켜진 칸을 가리킨다 |
| 장바구니 버튼을 중성 테두리로, 바로구매만 채움 | 나란히 놓였을 때 무엇을 눌러야 하는지가 색 하나로 갈린다 |
| 아바타·갤러리 빈 썸네일을 중성으로 | 강조색이면 목록마다 파란 점이 줄줄이 박힌다 |
| 주문서 안의 상품 줄에서 테두리를 걷고 구분선으로 | 바깥 카드가 이미 상자라 테두리가 두 겹으로 겹쳤다 |
| 합계 줄의 **마지막 금액만** 키움 | 실제로 낼 돈이 상품합계·배송비와 같은 크기면 눈이 그냥 지나간다 |

## 대비 (계산해서 맞춘 값)

본문 20.2:1 · 흐린 글 4.76:1 · 링크 5.82:1 · 조작 요소 경계 3.35:1 · 공지 칩 4.51:1.
어두운 모드도 전부 통과한다. **shadcn 원본은 테두리가 1.3:1 수준이라 그대로 베끼면 접근성이 후퇴한다** —
장식용 선(`--line`)과 조작 요소 경계(`--btn-line`)를 나눈 standard 의 구조를 그대로 지켰다.

## 본 화면 / 아직 안 본 화면

**본 화면** — 메인 · 게시판 목록 · 글 읽기 · 스토어홈 · 상품 목록 · 상품 상세 · 장바구니 · 주문서 ·
주문 상세 · 주문 내역 · 찜 목록 · 주문 완료 · 비회원 조회. 메인·상품 목록·상품 상세·주문 상세·찜 목록은
**어두운 모드까지** 봤다.

**아직 안 봄** — 회원가입 · 검색 결과 · 반품 신청 폼(배송완료 주문이 있어야 뜬다) ·
**눌러야 나오는 것 전부**(옵션 칩으로 줄 쌓기, 장바구니·찜 confirm 창, 관리자 반품 모달) · 모바일 폭.
헤드리스 브라우저로는 JS 상태를 만들 수 없어 이것들은 사람이 눌러 봐야 한다.

로그인이 필요한 화면은 세션을 만들 수 없어, 뷰에 넘어가는 자료를 실제 DB 에서 만들어
블레이드만 돌려서 봤다(`scratchpad/render_rest.php` 방식).

> 템플릿은 `standard`(이것)와 `old-standard` 둘뿐이다. `graphite`·`night`·`picnic`·`coral` 은
> 카트 모듈보다 먼저 만들어져 쇼핑몰 화면·CSS 가 아예 없어 걷어냈다(2026-08-09).
> 되살리려면 그 커밋을 되돌리면 된다.
